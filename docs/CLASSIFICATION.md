# 深市 ETF 归类方法 · CLASSIFICATION

本文说明 `scripts/classify.mjs` 如何把**深市 864 只场内 ETF** 归入现有 **86 个细分行业**，
以及为什么这样归、哪些地方需要人工拍板。

产物：`data/universe.json`（合并用）、`data/universe-report.json`（审查用）。
合并消费方：`lib/universe.mjs`（只读 `assign / names / sources / newSubs`）。

---

## 1. 边界：只加不改

| 对象 | 处理 |
| --- | --- |
| 沪市 773 只成分的 86 小类归属（`lib/taxonomy.mjs`） | **只读**，一个字节都不改；`verify:origin` 依赖它 |
| 深市 864 只场内 ETF | 本脚本新增归属，落到**同名**的 86 小类上，或落到 `newSubs` 新增小类 |
| 数据库（`data/etf.db`） | 只读，不写入 |
| `lib/`、`web/`、`site/`、`server/`、`tests/` | 不改 |

「深市 864 只」= Tushare `fund_basic(market=E)` 里 `ts_code` 以 `.SZ` 结尾且名称含 `ETF` 的全部记录
（含 LOF/联接、含已退市 47 只；退市但仍在名录里的照归，因为份额序列在库中仍存在）。

## 2. 数据来源与调用纪律

```
Tushare fund_basic(market=E)  ·  1 次调用覆盖沪深全部 3037 只场内基金
  字段：ts_code, name, benchmark, invest_type, fund_type, status, list_date, delist_date
```

* **限流**：走 `lib/tushare.mjs` 的 `call()`，自带全局令牌桶（默认 120 次/分钟）+ 单次运行预算 + 每日预算，
  本脚本**不做任何并发**，全程只有 1 次 API 调用。
* **缓存**：结果写 `os.tmpdir()/etf-flow-fundbasic-<YYYY-MM-DD>.json`（不进仓库）。
  `--force` 忽略缓存重新拉取；缓存过期自动重取；网络失败时若有旧缓存则降级使用。
* **为何用 benchmark 而不是基金名**：`benchmark`（业绩比较基准）里带**跟踪指数全名**，
  例如 `158088.SZ 博时创业板电池ETF → 创业板电池指数收益率×100%`；
  基金名会被渠道改写成营销口径，指数名是唯一能跨市场对齐的口径。

## 3. 归一化：指数指纹（`indexFingerprint`）

index 级要求「同一只指数」，所以必须把 benchmark 洗成**不带噪声的指数名**。四步：

1. **取主成分**：按 `+` 拆分后，按权重取最大的**非现金**成分。
   解决 `活期存款利率(税后)×5%+沪深300指数×95%` 这类复合基准——
   直接取第一段会得到「活期存款利率」，把 6 只联接基金错判成一堆小类。
2. **去权重尾巴**：`×100%`、`*95%`。
3. **去括号内容**：`(港元)`、`(经估值汇率调整)`、`(S&PAccessHongKong…)`。
4. **去口径/币种/形态噪声**：`收益率 / 同期 / 全收益 / 净价 / 价格指数 / 港元 / 人民币 /
   交易型开放式 / 证券投资基金 / 发起式 / 联接 / 基金 / ETF / LOF`，并砍掉句尾的 `指数`。

示例：

| benchmark | 指纹 |
| --- | --- |
| `创业板电池指数收益率×100%` | `创业板电池` |
| `中证港股通信息技术综合指数(港元)收益率×100%` | `中证港股通信息技术综合` |
| `经估值汇率调整后的国证港股通科技指数收益率×100%` | `国证港股通科技` |
| `活期存款利率(税后)×5%+中证小盘500指数×95%` | `中证小盘500` |
| `中证电池主题指数×100%` | `中证电池主题` |

基金名另有一条轻量归一（`cleanFundName`）：摘掉基金公司词（含「前海开源」「南方东英」这类
会被区域/海外规则误命中的多字公司名）+ `ETF/联接/QDII/LOF/份额类别`，
只作为规则的补充召回，不参与 index 级。

## 4. 三级匹配（顺序即优先级）

| 级别 | 依据 | 判定 | 当前数量 |
| --- | --- | --- | --- |
| `index` | 指纹与某个**沪市成分**的指纹完全相同 | 直接继承该沪市成分的小类 | 391 |
| `rule` | `RULES` 数组顺序匹配（首个命中者胜） | 归入现有 86 小类之一 | 380 |
| `new` | 同上，但命中的目标是 `newSubs` | 归入新增小类 | 70 |
| `unassigned` | 都不匹配 | 进报告，交人工 | 9 |

覆盖率：`(391+380+70) / (864-14) = 98.94%`；占 864 全量 97.34%。
（分母剔除 14 只非股票/债券 ETF，见第 5 节。）

**指数指纹冲突**：同一指纹若同时命中多个小类，不静默取一个——
写入报告 `conflicts`，并取「沪市成分数最多」的小类，同时保留 `candidates` 供复核。当前 0 条。

当前 index 级能覆盖 391/850，剩余靠规则，是因为深市大量 ETF 跟踪**深证/国证系**指数
（创业板、国证粮食产业、国证自由现金流、恒生港股通…），这些指数沪市没有对应 ETF。

## 5. 排除层（不是股票/债券 ETF，现有体系无对应小类）

按 `invest_type` / benchmark / 名称判定，共 **14 只**：

* `货币型`（3 只）：场内货币 ETF；
* `黄金现货合约`（8 只）：跟踪金价（上海金、Au99.99），不是股票；
* `*期货型`（3 只）：豆粕、有色金属、能源化工商品期货 ETF；
* `REITs`（本批 0 只）：名称含 `REIT`。

**注意区分**：「中证沪深港黄金产业股票」是**黄金股**（贵金属小类，4 只），不是黄金现货，
必须归入 `6_资源 / 贵金属`，不能排除。判断依据是 `invest_type`，不是名称里有「黄金」。

**主动管理 ETF（9 只）→ `unassigned`**：它们的 `benchmark` 只是业绩比较基准（中证800/A500/中证红利），
并不跟踪指数。若按基准归入「A股中盘」之类，会把不看指数的主动产品塞进指数行业口径，
稀释「小类份额=成分 ETF 份额之和」的含义，因此显式不归类，交人工决定
（详见第 8 节争议项 1）。

## 6. 规则表结构（`RULES`）

```js
{ id: "battery", re: /电池|储能/, sub: "电池", why: "电池/储能电池/新能源车电池指数" }
```

* 匹配对象：`` `${指数指纹} ${cleanFundName(name)}` ``；
* **顺序即优先级**，首个命中者胜，先精确后宽泛；
* 排序原则：债券 → 境外 QDII → 港股专项 → **航空航天** → 区域 → 科技/医药/能源/制造/资源/金融/消费
  → 风格策略 → 宽基 → 「含 `科技`」的宽泛兜底；
* 每条规则的命中数见报告 `ruleTable[].hits`，`--review` 会打印全表。

### 排序为什么这么排（踩过的坑）

| 坑 | 现象 | 对策 |
| --- | --- | --- |
| 债券太晚 | `中证AAA科技创新公司债` 被 `科技` 吃掉 | 债券规则整体前置 |
| 科技太宽 | `国证疫苗与生物科技`→科技综合、`中证智选航空航天科技`→科技综合 | `科技` 兜底放到**规则表最后一行** |
| 证券 vs 深证成指 | `深圳证券交易所成份` 含「证券」，被 `券商` 吃掉 | 券商规则收窄成 `证券公司/证券行业/证券龙头/券商` |
| 卫星 vs 通信 | `国证商用卫星通信产业` 被 `通信` 吃掉 | 航空航天规则前置到科技之前 |
| 消费电子 vs 电子 | `国证消费电子` 会被 `电子`→半导体吃掉 | 消费电子规则先于半导体 |
| 红利 vs 央国企 | `中证国有企业红利` 应进红利而非央国企 | 风格段内「红利→现金流→价值→成长→央国企→ESG」 |
| 工业互联网 vs 互联网 | `中证工业互联网主题` 应进云计算与数据 | 云计算规则先于互联网 |

**零命中规则（当前 31 条）是有意保留的兜底**：这些主题的指数在沪市已有同名成分，
当下全部由 index 级承接；保留是为了深市后续新发同主题 ETF、或沪市该指数退市后仍有规则可依。

## 7. 新小类（`newSubs`）判定标准

只有同时满足才建：① 深市同主题 ≥3 只；② 现有 86 小类里没有可沿用的口径。当前 2 个，都在 `1_宽基市场`：

| 小类 | 大类 | 颜色 | 只数 | 依据 |
| --- | --- | --- | --- | --- |
| `创业板宽基` | `1_宽基市场` | `#C8562A` | 50 | 该大类只有科创板宽基 + A股/港股宽基，**创业板口径整块缺失**（创业板指/50/200/综合/300/大盘） |
| `海外宽基` | `1_宽基市场` | `#E8A277` | 20 | 现有 86 小类只覆盖 A 股与港股，纳斯达克100/标普500/日经225/德国DAX/沙特/巴西/亚太等境外宽基无归属 |

**没有**为「创业板电池/创业板软件/港股科技/港股医药/港股消费」新建小类：
现有 86 小类已经用「港股通科技归科技综合、港股通汽车归汽车与零部件、港股通医药归医药综合」的口径
处理了港股行业主题，创业板行业主题按同一逻辑并入对应行业小类即可，新建会让口径碎片化。

### 沿用的既有口径（值得记住）

* `中证科创创业50`（双创50）在沪市口径里归 `科创板宽基`，深市 6 只同指数 ETF 由 index 级继承；
* 港股行业主题并入同名 A 股小类（科技综合/互联网/医药综合/创新药/生物医药/消费综合/汽车与零部件/金融综合/银行/券商）；
* 港红利、港股宽基单列（`港红利股息`、`港股宽基`）。

### 少数按「最接近口径」归入、可讨论的

| 指数 | 小类 | 理由 |
| --- | --- | --- |
| `创业板算力基础设施`（10 只） | `云计算与数据` | 沪市无「算力」小类；该小类已含物联网/大数据/数据中心类基础设施 |
| `中证虚拟现实主题` | `消费电子` | VR/AR 属终端硬件，沪市无 VR 小类 |
| `中证全指工业` | `高端装备` | 工业综合指数，该小类已含「中证装备产业」 |
| `中证工业互联网主题`（4 只） | `云计算与数据` | 与物联网/数字经济同口径，规则需先于「互联网」 |
| `标普中国新经济行业` | `综合策略` | 跨行业新经济综合，非单一行业 |
| `国证财富管理` | `金融综合` | 券商/银行/保险混合 |

## 8. 需要人工拍板的争议项

1. **主动管理 ETF（9 只）**：现按「不跟踪指数」记 `unassigned`。
   若希望看板覆盖它们的份额，可按 benchmark 归入（中证800→A股中盘、中证红利→红利股息、中证A500→A股全指）。
2. **`创业板算力基础设施`（10 只）**：归 `云计算与数据`，也可考虑并入 `人工智能`，或单列「算力」。
3. **`双创50`（6 只）继承 `科创板宽基`**：指数本身 50% 科创板 + 50% 创业板，若认为该并入 `创业板宽基`，需同时改沪市口径（不建议）。
4. **`创业板低波价值`**：现归 `价值策略`（按「价值」），也可归 `红利低波`。
5. **`港股科技`类（21 只）并入 `科技综合`**：与沪市口径一致，但会让科技综合从 29 只涨到 62 只（沪深合并）；若希望单列「港股科技」，改一行新小类即可。

## 9. 复现与自检

```bash
node scripts/classify.mjs            # 生成 data/universe.json
node scripts/classify.mjs --report   # 另写 data/universe-report.json，打印分级统计 + Top10 增量
node scripts/classify.mjs --review   # 打印未归类全部 + 每条规则命中数 + 冲突
node scripts/classify.mjs --force    # 忽略缓存，重新拉 Tushare
```

脚本内置自检，任一不满足即抛错退出：

* `assign` 里出现沪市成分代码 → 报错（保证不动原口径）；
* 归到不存在的小类 → 报错；
* 新小类所属大类不存在 → 报错；
* `assign` 与 `excluded` 出现同一代码 → 报错。

### 产物字段

`data/universe.json`

| 字段 | 说明 |
| --- | --- |
| `generatedAt` | 生成时间（ISO8601） |
| `assign` | `6 位深市代码 → 小类名`（841 条） |
| `names` | `6 位深市代码 → ETF 名称`（合并时渲染用） |
| `sources` | `6 位深市代码 → index/rule/new`（合并时统计归属层级） |
| `newSubs` | `小类名 → { cat, color, baseOn, reason, count }` |
| `excluded` | `6 位代码 → 排除理由`（14 条） |

`data/universe-report.json`：`counts`（分级统计）、`conflicts`、`unassigned`（全部，含一句话理由）、
`unassignedByReason`、`ruleTable`（每条规则命中数与示例）、`ruleZeroHit`、`subIncrements`
（每个小类 before/added/after，按增量降序）、`newSubs`、`source`（数据来源与指纹数）。

### 维护指引

* **新增/调整规则**：改 `RULES` 数组，保持「精确在前、宽泛在后」，跑 `--report` 看命中数变化，
  `git diff data/universe.json` 应该只有预期的几百条内变化。
* **新增小类**：先在 `NEW_SUBS` 里加（`cat` 必须存在于 `CATS`，`color` 与所属大类同色系），
  再加一条指向它的规则；合并侧 `lib/universe.mjs` 会自动建容器。
* **不要**在脚本里改沪市成分，也不要在规则里写基金公司名（基金名已被归一化，写公司名是死路）。
