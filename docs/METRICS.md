# 指标口径（v4.0.0 起）

## 一、为什么去掉「份额」

份额（份/亿份）**不是可加量**：

- 债券 ETF 面值 100 元/份，股票 ETF 面值 1 元/份，同样 1 亿元规模，份数差 100 倍；
- 同一指数的不同 ETF 面值也可能不同；
- 所以「某类 ETF 合计份额」跨标的、跨类别都**没有经济含义**，只在同类同质标的之间勉强可比。

真正可加的是**钱**：规模（亿元）与净申购（亿元）。v4.0.0 起界面只保留三个指标，
份额仍保留在数据库内部（`share` 表），仅用于计算净申购，不再对外展示。

## 二、三个指标的定义

| 指标 | 定义 | 单位 | 可加性 |
| --- | --- | --- | --- |
| **规模** | `Σ(份额_亿份 × 单位净值)` | 亿元 | ✅ 可跨标的、跨类别相加 |
| **净申购** | `Σ((份额_t − 份额_{t−1}) × 净值_t)`，按一级市场申赎计 | 亿元/日 | ✅ 可加，可跨期累加 |
| **变化率** | 区间口径的相对变化（见下） | % | 无量纲，仅同类可比 |

### 净申购的口径要点

1. **只算一级市场申赎**：份额变动才产生净申购，二级市场买卖不改变份额，不计入。
2. **用当日净值**换算：`Δ份额(亿份) × 当日单位净值(元)`。
3. **份额折算还原**：拆分/合并（`event` 表）会改变份数但不变资金，须先折算到同一份数单位再作差。
4. **上市首日不计入**：新股首日无前值，不产生"申购"。
5. **缺净值日跳过**：净值缺失时该只标的当日不贡献流量，并在覆盖率里体现。

### 变化率的两种口径（必须区分）

- **流量口径（默认）**：`区间净申购 / 期初规模`，衡量"这段时间净流入相当于期初规模的多少"；
- **规模变化率**：`(期末规模 − 期初规模) / 期初规模`，包含净值涨跌的影响。

两者在净值有波动时**不相等**：`规模变化率 ≈ 流量口径 + 净值涨跌幅`。
界面上以**规模变化率**作为"变化率"（用户直觉：规模涨了多少），
"净申购"单列一栏体现资金进出，两者并列时能互相解释差异。

## 三、覆盖率与不可信区间

早期（2021–2023）数据是逐步回补的，某些小类在部分交易日只有零星成分有数据，
此时小类合计会出现"台阶"。这类点**不应被当成资金流**：

- 每个小类每日输出 `coverage = 当日有数据的成分数 / 成分总数`；
- `coverage < 0.6` 的日期标记为**低覆盖**：折线画虚线 + 灰底，区间指标的首尾自动向前取最近达标日；
- 低覆盖日的值仍然保留（不做插值、不改数），但必须视觉上可识别。

## 四、派生与聚合的层次

```
每只 ETF 每日：份额(万份) × 净值(元) / 1e4 → 规模(亿元)
                Δ份额(万份) × 净值(元) / 1e4 → 净申购(亿元/日)
小类每日：      Σ 成分规模、Σ 成分净申购（只累加有数据的成分）
全市场每日：    Σ 各小类（同一时点，避免小类间重复计数）
```

分类口径（v2 / legacy）不同，聚合结果不可混用；切换口径时整站数值都会变，属于预期行为。

## 五、实现说明（v4.0.0）

本节的每条都能在代码里找到对应实现：`lib/metrics.mjs`（指标算术）、`lib/pipeline.mjs`（落库）、`lib/payloads.mjs`（载荷）、`lib/build/site.mjs`（分片与开关）。

### 5.1 coverage 与聚合同源

- `coverage = 当日真正参与聚合的成分数 / 成分总数`，不是「数据库里有几行」；
- 与 `recomputeAll` 的 `eff` 集合**同一口径**：`filterIsolated`（孤立披露）剔除的行、以及官方口径日被丢弃的 Tushare 兜底行，都**不计入命中**；
- 精度：库内 `series.coverage` / `series_v2.coverage` 4 位小数；`site/data/subs.json` 2 位小数（体积考虑）；
- `quality.json.lowCoverageDays = { threshold: 0.6, total, subs, top[] }`：`coverage < 0.6` 的 (小类×日) 汇总，前端据此画虚线/灰底，并让区间指标首尾向前取最近达标日；
- 低覆盖日**不做插值、不改数**。

### 5.2 区间净申购含期初当天

- `etfRanges[period][code].flow = Σ(区间内每个交易日的逐 ETF 净申购)`，**包含期初当天**——
  期初当天的 Δ 对应「期初前一日 → 期初」的真实申赎，与 `series.flow` 的逐日求和在同区间一致；
- 若按「期末减期初」理解会差一天，跨期比较时请以本口径为准。

### 5.3 区间窗口与月末对齐

- 期初 = **最后一个 ≤（末日 − N 个月）的交易日**（保证窗口至少覆盖整个周期，而不是被截短）；
- 历史不足 N 个月 → 期初退到第 0 个交易日；
- 月份加减按 UTC 且**月末对齐**：`3-31 − 1 月 → 2-28/29`；
- 六个区间（1m/3m/6m/1y/3y/5y）恒有输出，缺数据时值为 `null`。

### 5.4 缺值一律写 null，不写 0

缺净值、期初无数据、成分当日无数据 → 规模 / 净申购 / 变化率均写 `null`；0 会被误读成「规模归零」或「零申购」，一律不用。

### 5.5 份额折算还原（v4.0.0 修正）

逐日净申购的分母口径是「同一份额单位」：

```
Δ = adj(份额_t,      日期 t 之后的事件) × 净值_t
  − adj(份额_{t−1}, 日期 t−1 之后的事件) × 净值_t
```

**前值必须用「前一日」的折算基准**。若两者都用当日基准，拆分/合并当天的份数变化会被当成申赎——
实测 `510310` 在 `2024-09-20` 合并（ratio 0.512）时，旧实现把 `A股大盘` 当日净申购算成 **−1846.79 亿元**，
修正后为 **+57.49 亿元**（约 1904 亿的假流出）。本次一并修正后，legacy 共 172 个 (小类×日) 的 flow 值发生变化。

### 5.6 `SUB_SERIES` 开关与体积

- `subs[].scaleSeries` **默认不下发**，改为 `scaleSeriesSource: "charts"`：
  规模序列的唯一来源是 `charts-<cat>.json` 的 `series[].scale`（同为 1 位小数），subs 再存一份是纯重复；
- 构建开关（无需改代码）：
  | `SUB_SERIES` | subs.json gzip | 相对 v3.12 | 说明 |
  | --- | --- | --- | --- |
  | `flow`（默认） | ≈170 KB | 0.76× | 只带 `flowSeries` + `coverage` |
  | `all` | ≈330 KB | 1.48× | 额外自带 `scaleSeries`（调试/离线单文件场景） |
  | `none` | ≈76 KB | 0.34× | 只带 `coverage`，两条序列都从 charts 取 |
- `etfRanges` 按大类拆到 `etf-ranges/<cat>.json`，结构：
  `{ cat, periods, unit, subs: { 小类名: { 1m: { code: { chgPct, flow, scaleEnd } }, … } } }`，按需加载。
